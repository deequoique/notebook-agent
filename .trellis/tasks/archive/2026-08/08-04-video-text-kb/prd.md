# 跨平台个人知识库 视频+图文 时间戳级检索

## Goal

用户可以用任何方式把**视频和图文**送进统一个人知识库，系统在**时间戳/段落级别**理解内容，帮助重新找到、整理和使用曾经收藏的内容。

平台 API 是可替换的 Connector，不是产品命门。

## 关键约束（来自实测，2026-08-04，新加坡机房 IP）

### 视频平台

| 结论 | 证据 |
|---|---|
| YouTube 直接爬字幕**已死** | timedtext baseUrl → HTTP 200 + `content-length: 0`。试过完整浏览器头 / Referer / Origin / consent cookie / `fmt=json3｜srv3｜vtt` / `c=WEB` 全为空。手写 Innertube 也不行（WEB→`UNPLAYABLE`，ANDROID→400） |
| yt-dlp 能绕过 | 走 `android vr` 客户端，**12/12 成功**，约 4s/个，带时间戳 json3，157 种语言 |
| 429 是**单视频级** | 某视频 429 时其他视频立即成功。可重试，非硬墙 |
| YouTube 有 chapters | 6 个视频中 4 个有 10–17 章，人工分段，切分器第一优先级信号 |
| B站元数据免 cookie | `x/web-interface/view` → `code:0`，含 title/desc/duration/pubdate/cid/aid/owner。连打 12 次全 `code:0`，无限流 |
| B站字幕**必须登录** | 匿名测 24 个（14 热门 + 10 知识区）**全部** `subtitles: []`，补 `buvid3` 无效 |
| B站音频可匿名下载 | format 30216，7.4min = 3.7MB → 服务端 ASR 兜底可行 |

### 图文平台

| 平台 | 结论 | 证据 |
|---|---|---|
| **微信公众号** | **完全可读，免鉴权** | 真实文章 URL → HTTP 200 / 3.37MB，`msg_title` 可取，发布时间戳 `1705487684`，**正文 2225 字符**，**77 张图**。无 `环境异常` |
| **小红书** | **硬封** | 图文笔记页 → **HTTP 302**，伪造 `xsec_token` 仍 302。`noteDetailMap` / `__INITIAL_STATE__` / `imageList` 全为 0，拿不到任何正文 |
| **知乎专栏** | **403** | 直接 HTTP 403，650 字节 |

### 小红书/抖音：token 解决不了

签名与认证是**两道独立的门**，常被混为一谈：

- XHS `search/notes` → `-101 无登录信息`（**认证**门）
- XHS `feed` → **HTTP 406**（**签名**门）
- 抖音 `iesdouyin` → `11110 encrypt_data_miss`（**签名**门，报错直接点名"加密数据缺失"）
- 抖音 `web/aweme/detail` → 200 + **0 字节**（静默拒绝）

签名必须由页面 JS 计算，**与登录态无关**。带上用户 token 过了认证门，仍会被签名门拦住。唯一可行路径是扩展内抓取。

### 内容处理

| 结论 | 证据 |
|---|---|
| 英文字幕标点不可靠 | 10 轨中 8 有标点，1 个视频**句号逗号全为 0** |
| 中文字幕**无任何切分信号** | 3 个视频 `gap>=2s` 出现 **0 次**、句末标点 **0 个** → 切分器退化硬切，**19/20 片段撞 120s 上限** |
| 中文密度 279 汉字/分钟 | 英文 168 词/分钟，阈值必须按语言分设 |
| 中文 ASR（M1 CPU int8） | `small` = **1.8x 实时**（445s 音频耗 242s），可用；`tiny` = 13.4x 但碎片化不可用 |
| 嵌入成本可忽略 | 1000 视频 × 15min ≈ 340 万 token ≈ **¥1.7**（智谱 Embedding-3，不含语义切分的额外调用），向量维持 1536 维 |
| 去重需求真实存在 | 两个不同 video_id（`bOlVx5zeHLM`/`dIyQl99oxlg`）转录**逐字节相同**（「重制版」重上传）→ 转录哈希是可靠去重信号 |

## Requirements

### 已确认决策

1. **混合架构**：MV3 扩展在用户已登录会话中抓取，只把文本 POST 给服务端；服务端做切分/嵌入/检索，**永不存储平台 cookie**
2. **MVP 1 平台**：YouTube + B站（视频）+ 微信公众号（图文）
3. **转录策略**：官方/自动字幕优先，ASR 仅在无字幕且用户显式要求时触发
4. **检索验证顺序提前**：向量 vs BM25（trigram 中文回退路径）双路对比在 P0 就跑起来。原因是中文检索路径（`pg_trgm`）和英文路径（`to_tsvector`）能力差异未经验证，越早发现召回差距，越早能反哺 P3 的中文切分降级链设计；RRF 融合与 rerank 留在 P4（融合参数本身是待验证假设，不应该和「两路各自是否可用」混在一起判断）
5. **不做小红书**：即使实测发现小红书网页版对部分笔记会把正文写进服务端渲染的 HTML（移动端 UA 直连读取，无需登录/签名，见 Notes），仍不纳入 MVP——并非所有笔记都走这条路径（部分笔记服务端不带正文、仍需签名 API），且图文笔记普遍无时间轴，知识密度低，投入产出比最差（与已有决策一致，不因这条新发现的路径改变结论）
6. **嵌入改用智谱 Embedding-3**：继续输出 1536 维以保持现有 pgvector schema；每次 API 请求最多发送 64 条文本，超出时顺序拆批。检索仍保留向量与 BM25/trigram 双路对比。
6. **Agent 工具层提前到 P1**：P0 证明 embedding 数据库可用后，下一需求直接实现「自然语言 → Agent 自主选择只读检索工具 → 查询 pgvector/元数据 → 带证据回答」。首个入口用 CLI，不等待 Web UI 或浏览器扩展；RRF/rerank 仍作为后续检索增强，不阻塞 Agent 闭环。

### 统一内容模型（视频 + 图文 all-in-one）

图文不是视频的特例，需要统一抽象但保留差异：

- 统一为 `content_item`（有 `kind`: `video` / `article`）
- 统一为 `segment`，但定位符不同：视频用 `start_sec`/`end_sec`，图文用 `char_offset`/`anchor`（段落序号或标题锚点）
- 检索返回的「跳转」语义不同：视频跳到时间点，图文跳到段落位置
- **不要**给图文伪造时间戳，也**不要**为图文单开一套检索链路

### 分工

| 数据 | 位置 | 原因 |
|---|---|---|
| YouTube 元数据 + 字幕 + chapters | 服务端 yt-dlp | 实测机房 IP 12/12 成功 |
| B站元数据 | 服务端 view API | 实测免 cookie、无限流 |
| B站字幕 | **扩展** | 实测匿名 24/24 拿不到 |
| B站音频 → ASR | 服务端 | 实测可匿名下载 |
| 微信公众号图文 | 服务端 | 实测免鉴权，正文 + 图片可取 |
| 小红书 / 抖音 / 知乎 | **不做** | 签名门槛 / 302 / 403 |

### 必须解决的两个真问题

**1. 中文字幕无切分信号** — 分级降级链：

| 级 | 信号 | 适用 |
|---|---|---|
| 1 | YouTube chapters | 实测 4/6 有 |
| 2 | cue 间隔 `>= 2.0s` | 英文有效，中文无效 |
| 3 | 句末标点 | 英文 8/10，中文基本无效 |
| 4 | **语义切分**（相邻 cue 嵌入，余弦相似度骤降处切开） | 中文唯一可靠兜底 |
| 5 | 固定长度硬切 + **15–20% 重叠** | 最后防线 |

中文按**字符数**、英文按**词数**设阈值，不共用数字。

**2. 「静默空成功」必须显式检测** — 失败形式是 HTTP 200 + 0 字节，不是异常，`raise_for_status()` 抓不到。这是最危险的失效模式：pipeline 看起来正常但什么都没索引。

- 转录写入前校验 `len(body) > 0` 且能解析出 `>= 1` 个带文本 cue
- 「200 但 0 字节」记为**失败**并重试
- 监控**空响应率**而非仅异常率
- 429 按**单视频**指数退避，不因单视频暂停整个队列

### 数据模型要点

- `transcript_source` 枚举：`official_cc` / `auto_caption` / `asr_whisper` / `article_text` / `none` — 检索结果必须能告诉用户文字来源，直接影响可信度
- **原始 json3 / 原始 HTML 逐字保存**到对象存储。重新切分不需重新抓取 — 最重要的一条防御，平台随时可能再收紧
- `content_hash` — 实测两个不同 video_id 转录逐字节相同，去重可靠信号
- `chapters` JSONB — YouTube 免费给的分段
- 用户侧：`why_saved`（收藏理由）、`watch_state`、`saved_at`
- 中文全文检索**不能用 `to_tsvector('english')`**。中文无空格，需 `pg_trgm` 或 bigram 方案
- 向量索引用 **HNSW**（非 IVFFlat）：个人库写入频繁、数据量小，无需训练且召回更好

### 技术选型

FastAPI + Celery/Redis · PostgreSQL + pgvector · MinIO/S3 · Next.js · WXT 扩展 · LangGraph 工具层

**放弃 LlamaIndex** — 已自定义 connector、切分器、混合检索、工具层，这几乎是框架全部作用面，加进来只是在 `psycopg` 上套一层间接。

## Acceptance Criteria

- [ ] **P0**：服务端 yt-dlp 摄入 + 时间戳切分 + pgvector（向量）+ BM25（trigram 中文回退）双路检索 CLI。摄入 20 个真实视频（含 1 个无标点英文、1 个中文），检索只在视频中段出现的概念，跳转过去确实是那句话；并排观察两路结果，记录中文查询下 trigram 召回相对向量的差距
- [ ] **P0 回归**：mock 返回 200 + 0 字节的 timedtext，确认摄入任务标记为**失败**而非成功
- [ ] **P0 回归**：连续摄入 15 个视频，单个 429 不中断队列
- [ ] **P1**：自然语言检索 Agent。用户通过 `ask` 输入自然语言问题，Agent 自主调用 `search_segments` / `get_neighbors` / `get_item` / `open_at` 查询 P0 建成的 embedding 数据库，并返回基于证据的答案、来源标题和可点击时间戳。知识库无证据时必须明确说未找到；首版只读，不得触发转录或修改数据
- [ ] **P2**：扩展一键保存 + Web UI + 点击跳转到时间点。完整闭环
- [ ] **P3**：B站元数据 + 扩展捕获B站字幕 + 中文切分降级链。中文视频撞上限片段比例显著低于基线 19/20
- [ ] **P3**：微信公众号图文摄入，段落级检索 + 跳转到段落。视频与图文在同一检索结果中正确混排
- [ ] **P4**：混合检索（BM25 + 向量 + RRF + rerank），增强 Agent 对「偏工程实践而非论文」这类带偏好查询的处理
- [ ] **P5**：ASR 按需触发 + 去重（内容哈希）+ 自动标签
- [ ] **CI**：每周跑一次真实摄入。yt-dlp 是唯一单点依赖，必须有回归信号

## Notes

- yt-dlp 是唯一单点依赖且必须接受：实测手写 Innertube 不可行、直接爬 timedtext 返回空，无更好替代。缓解：原始文件永久缓存 + 每周 CI 回归 + 装 deno（yt-dlp 已警告缺 JS runtime）
- 小红书/抖音短视频知识密度低，图文笔记无时间轴，即使技术打通投入产出比仍最差
- 微信公众号无搜索/发现 API，只能按 URL 读取 → 用户需主动分享/粘贴链接，与「扩展一键保存」模式天然契合
