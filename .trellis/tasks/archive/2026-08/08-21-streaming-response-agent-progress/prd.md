# 流式响应与 Agent 进度可见性

## Goal

将 Agent 的执行结果改为可增量传输的流式响应，并在用户界面持续展示当前 Agent 正在进行的高层阶段与进度，让用户无需等待整个请求结束后才获得反馈。

本任务只要求展示可向用户公开的活动摘要（例如“正在检索资料”“正在整理答案”），不暴露隐藏推理、系统提示词、凭据或其他内部实现细节。

## Requirements

- 后端能够在一次 Agent 请求期间按顺序发出增量事件，至少覆盖：请求开始、阶段/活动更新、文本增量、正常完成、失败和取消。
- 流式事件包含稳定的请求/消息标识、事件类型、产生顺序以及前端渲染所需的最小负载；断线、重复或乱序事件不会静默破坏最终消息。
- 前端在收到事件后即时更新回答内容，并显示当前活动摘要及明确的进行中、已完成、失败或已取消状态。
- 活动摘要来自受控的状态集合或等价的安全映射，不能直接把内部工具调用参数、原始日志或模型隐藏思维发送给用户。
- 流结束时生成与非流式路径一致的最终消息状态；错误信息对用户可理解，同时保留服务端诊断所需的上下文。
- 保留现有非流式调用的兼容行为，或提供明确的协商/降级路径，避免不支持流式传输的客户端无法使用 Agent。
- 提供环境变量 `AGENT_STREAMING_ENABLED` 控制服务端默认响应模式：未设置时默认开启流式；设置为 `false`、`0`、`no` 或 `off` 时默认关闭流式；设置为 `true`、`1`、`yes` 或 `on` 时显式开启流式。
- 环境变量遵循现有布尔配置的解析约定，非法值应在启动/配置加载时以明确错误暴露；变量及默认值同步记录在 `.env.example` 或等价的部署配置文档中。
- 为事件序列、连接中断/重连、错误、取消和非流式降级补充自动化测试，并记录必要的可观测性指标。

## Acceptance Criteria

- [ ] 用户发起 Agent 请求后，在最终答案完成前即可看到至少一次活动状态更新和文本增量（在服务端确实产生相应事件的情况下）。
- [ ] 正常请求按顺序完成“开始 → 活动/文本增量（零次或多次）→ 完成”，界面最终只呈现一条完整答案，不出现重复片段。
- [ ] Agent 失败或被取消时，界面在流结束前后都能进入对应终态，显示可理解的提示，并且不会把请求永久标记为进行中。
- [ ] 传输中断、重复事件或乱序事件有确定行为（重连、去重、丢弃或降级），且有测试覆盖；不得静默拼接出错误答案。
- [ ] 对外事件和界面活动文案不包含隐藏推理、系统提示词、敏感凭据或未脱敏的内部工具参数。
- [ ] 不支持流式的客户端仍可通过兼容/降级路径获得最终答案，现有非流式相关测试保持通过。
- [ ] 未设置 `AGENT_STREAMING_ENABLED` 时，服务端默认走流式路径；设置为任一支持的假值时默认走非流式路径；设置为任一支持的真值时默认走流式路径。
- [ ] `AGENT_STREAMING_ENABLED` 使用非法值时配置加载失败并给出包含变量名的可理解错误；`.env.example` 或部署文档展示该变量及默认开启行为。
- [ ] 自动化测试验证事件协议、前端状态转换、错误/取消处理和降级路径；相关指标或日志足以定位一次请求的流式生命周期。
